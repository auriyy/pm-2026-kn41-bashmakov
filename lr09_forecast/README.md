## 2. Як рахувалася симуляція

Для кожного сценарію проведено 10 000 прогонів Monte Carlo.

Використано рівноймовірний випадковий вибір історичних значень `points_done` із поверненням.

Генератор випадкових чисел: `random.Random(20261029)`.

Кожен вибір velocity відповідає одному спринту.

Симуляція завершується, коли накопичені points не менші за заданий обсяг роботи.

Відсортовані результати дають P50 і P85 за індексом `ceil(q × runs) - 1`.

Виконайте наведений код у Python 3. Окремий `.py` файл не потрібний.

```python
import math
import random
from datetime import date, timedelta


def forecast(values, points=220, runs=10000, seed=20261029):
    if points < 0 or runs < 1000 or not values or any(v < 0 for v in values):
        raise ValueError("Invalid inputs")

    if points and not any(values):
        raise ValueError("No positive velocity: no finite forecast")

    rng = random.Random(seed)
    results = []

    for _ in range(runs):
        remaining, count = points, 0

        while remaining > 0:
            remaining -= rng.choice(values)
            count += 1

        results.append(count)

    results.sort()

    return tuple(
        results[math.ceil(q * runs) - 1]
        for q in (0.50, 0.85)
    )


reference_samples = {
    "all12": [21, 17, 26, 14, 23, 6, 28, 12, 22, 25, 18, 9],
    "sprints1_2": [21, 17],
    "sprints5_6": [23, 6],
}

for name, values in reference_samples.items():
    p50, p85 = forecast(values)
    print(name, "P50", p50, "P85", p85, "width", p85 - p50)


own_velocity = [8, 16]

p50_full, p85_full = forecast(own_velocity, points=42)
p50_left, p85_left = forecast(own_velocity, points=18)

first_end = date(2026, 10, 9)
second_end = date(2026, 10, 23)

print(
    "Full:",
    p50_full,
    first_end + timedelta(days=(p50_full - 1) * 14),
    p85_full,
    first_end + timedelta(days=(p85_full - 1) * 14)
)

print(
    "Remaining:",
    p50_left,
    second_end + timedelta(days=p50_left * 14),
    p85_left,
    second_end + timedelta(days=p85_left * 14)
)


assert forecast([10], 20) == (2, 2)
assert forecast([10], 21) == (3, 3)
assert forecast([0], 0) == (0, 0)

try:
    forecast([0, 0], 1)
    raise AssertionError("Expected refusal")
except ValueError:
    pass

print("Boundary checks: PASS")
```

Результати з `seed=20261029`:

```text
all12 P50 12 P85 14 width 2
sprints1_2 P50 12 P85 12 width 0
sprints5_6 P50 16 P85 18 width 2
Full: 4 2026-11-20 5 2026-12-04
Remaining: 2 2026-11-20 3 2026-12-04
Boundary checks: PASS
```

Перевірки охоплюють точну кратність обсягу, необхідність додаткового спринта, нульову роботу та неможливе завершення за нульової velocity.

| Сценарій | Points | P50 (спринтів) | P85 (спринтів) | Дата P50 | Дата P85 |
| --- | ---: | ---: | ---: | --- | --- |
| Весь перший реліз | 42 | 4 | 5 | 2026-11-20 | 2026-12-04 |
| Залишок після двох спринтів | 18 | 2 | 3 | 2026-11-20 | 2026-12-04 |

Повний реліз обчислено від кінця першого спринта:

Дата = 2026-10-09 + (N − 1) × 14 календарних днів.

Для залишку:

Дата = 2026-10-23 + N × 14 днів.

Дату P85, 2026-12-04, називаємо більш консервативною оцінкою.

Це модельний прогноз.

Початок календарного плану ЛР7 — 2026-11-02, а навчальні спринти моделі починаються 2026-09-28.

Тому календарі не зіставні без узгодження: ранніша дата Monte Carlo не доводить, що критичний шлях на практиці буде коротшим.

За планом 49 робочих днів замість нормативних 40 перевищують строк на 9 робочих днів.

Після реальних двох спринтів потрібно перерахувати прогноз на фактичній velocity та зіставити дати на одній часовій основі.
