## 4. Критичний шлях

Дата старту: **2026-11-02**. У тижні п'ять робочих днів, свята не враховуються. 49 робочих днів займають період із 02.11.2026 до кінця 07.01.2027; датою готовності релізу в `roadmap.csv` зазначено наступний робочий день — 08.01.2027.

| Що | Значення |
| --- | --- |
| Критичний шлях | 49 робочих днів |
| Критичні гілки | T-01 → T-16 → T-05 → T-07 → T-08 → T-09 **або** T-10 → T-13 → T-14 → T-17 → T-18 |
| Дата завершення (дата готовності після 49 робочих днів) | 2027-01-08 |
| Строк V04 | 40 робочих днів |
| Різниця | +9 робочих днів |

**Чи вкладаємось:** ні. Навіть після паралельного виконання незалежних робіт розрахункова тривалість становить 49 робочих днів. Обрано збереження функцій REL-1 та перенесення дати на дев'ять робочих днів. Ціна рішення — порушення початкового строку. Альтернатива для повернення до восьми тижнів — скорочення критичних робіт або частини обсягу першого релізу після погодження із замовником; просте прискорення некритичних завдань не змінить дату завершення.

Найбільший резерв мають T-03 і T-04 — по 17 робочих днів. Вони відповідають плануванню, комунікаціям і ризикам та не блокують технічні роботи в поточній моделі залежностей. Це резерв CPM, а не дозвіл відкласти управління проєктом до кінця.

## 7. Робочий журнал

Спочатку план мав надмірно послідовні залежності й перевищував строк на десятки днів. Після звірки з попередніми лабораторними роботами уточнено оцінки пакетів, винесено управління проєктом у паралельний потік, а роботи розробників розподілено відповідно до їхньої зайнятості. Каталог і повідомлення виконує Dev 50%, тоді як основний процес заявок, погодження й перевірку конфліктів — Dev 100%.

Тестування поділено на ранні функціональні тести та окремі перевірки погодження і конкурентних запитів, що дає змогу не чекати завершення всіх модулів перед початком QA. Віхи погодження вимог і приймання тепер мають залежні наступні роботи. Після перерахунку отримано 49 робочих днів. Це на дев'ять днів більше за обмеження V04, тому рішення про перенесення дати слід погодити із замовником. Оцінки трудомісткості залишаються плановими припущеннями й потребують перевірки командою.
